Minimum spanning trees

1. The six towns, the eight candidate roads and the question from Lecture 10.1

Lecture 10.1 established three facts that this lecture uses. When every road has a positive cost, the cheapest connected plan has no cycle, so it is a tree. A tree with n vertices has n − 1 edges, so a tree on the six towns has 5 roads. This graph has 24 trees, and Cayley's formula showed that the number of trees grows far too fast to check them one by one on a larger map. Lecture 10.1 ended with a problem: find the cheapest tree without checking every tree. A second question comes with it. Once a method gives an answer, the county needs a way to be sure that no cheaper plan exists.

A spanning tree of a graph is a tree that contains every vertex of the graph and uses only edges of the graph. For the towns, a spanning tree is a connected road plan with no cycle that reaches all six towns. It has 6 − 1 = 5 roads.

A minimum spanning tree is a spanning tree whose total weight is as small as possible. When two edges have the same weight there can be more than one minimum spanning tree. On this map no two costs are equal.

Task 1 (about 3 minutes, calculator or Figure 1)

Twisp is the only town with a candidate road to every other town. The Twisp plan builds those five roads.

  1. Write one sentence saying why the Twisp plan is a spanning tree. Write its total cost.
  2. Replace Mazama–Twisp with Mazama–Winthrop. Write the new total, and check that every town can still reach Twisp.
Solution to Task 1

(a) Every town has a road to Twisp, so any two towns are joined by a path through Twisp, and the plan is connected. A cycle would need a road between two towns other than Twisp, and the plan has none. So it is a spanning tree, with 5 roads. Total: 223 + 86 + 239 + 261 + 270 = $1,079 million.

(b) 1,079 − 223 + 145 = $1,001 million, a saving of $78 million. Mazama now reaches Twisp by the path Mazama → Winthrop → Twisp. The other four towns still have their own road to Twisp.

One exchange lowered the cost by $78 million. Exchanging roads by hand gives no sign of when to stop. Kruskal's algorithm builds the cheapest tree directly.

2. Kruskal's algorithm

Joseph Kruskal published this method in 1956 [8]. It builds the tree one road at a time and always takes the cheapest road that does not make a cycle. To spot cycles it keeps the towns in groups, as in Lecture 10.1 Task 3(c): two towns are in the same group when the roads built so far already join them by a path.

Kruskal's algorithm, for a connected graph with n vertices

  1. List all edges in order from cheapest to most expensive.
  2. Start with no edges built. Each vertex is a group by itself.
  3. Take the next edge on the list.
    • If its two vertices are in different groups, build it, and merge the two groups into one.
    • If its two vertices are already in the same group, skip it.
  4. If you have built n − 1 edges, stop. Otherwise go back to step 3.

The reason for each step:

  • Step 3 skips an edge when its two vertices are in the same group. A path of built edges already joins them, and that path together with the new edge would form a cycle. When the two vertices are in different groups, no path joins them yet, so the new edge cannot close a cycle.
  • Step 4 stops at n − 1 edges because a tree on n vertices has exactly n − 1 edges. At that point every vertex is in one group.
  • Step 1 is what makes the result the cheapest tree. Section 4 gives the reason.

3. Checking that the result connects every town

Kruskal's tree has 5 roads, which is n − 1 for n = 6 towns. It has no cycle, because the algorithm skips every road that would close one. It is connected, because after row 7 all six towns are in one group. Task 3 checks the last point directly on the map.

Task 3 (about 2 minutes, paper or Figure 2)

Using only the five roads of Kruskal's tree, write a path from Brewster to each of the other five towns.

Solution to Task 3
  • Brewster → Pateros
  • Brewster → Pateros → Twisp
  • Brewster → Pateros → Twisp → Winthrop
  • Brewster → Pateros → Twisp → Winthrop → Mazama
  • Brewster → Pateros → Twisp → Winthrop → Conconully

Every town can reach Brewster, so any two towns can reach each other by going through Brewster, and the plan is connected. In a tree there is exactly one path between two towns, since a second path would close a cycle.

4. Why no cheaper tree exists: the swap test

A swap changes a spanning tree by one road:

  1. Add a road that is not in the tree. Its two towns were already joined by a path in the tree, so the new road closes exactly one cycle.
  2. Remove a different road on that cycle. The plan stays connected, because a trip that used the removed road can go the other way around the cycle (Lecture 10.1, Section 5). It has 5 roads again and no cycle, so it is again a spanning tree.
  3. The new total is the old total, plus the cost of the added road, minus the cost of the removed road. It is lower only if the removed road costs more than the added one.

Task 4 (about 6 minutes, Figure 1 or paper)

In Figure 1, click "Remove all roads" and then click the five roads of Kruskal's tree. The total should read $798 million.

  1. Add Twisp–Conconully (239). Name the towns on the cycle that forms and the two tree roads on it. Remove the more expensive of the two tree roads. Write the new total and the change from 798.
  2. Do the same for the other two roads that are not in the tree: Mazama–Twisp (223) and Twisp–Brewster (270). Start from Kruskal's tree each time.
  3. Write whether any swap lowered the total.
Solution to Task 4

(a) Adding Twisp–Conconully (239) closes the cycle Twisp → Winthrop → Conconully → Twisp. Its tree roads are Winthrop–Twisp (86) and Winthrop–Conconully (224). Removing Winthrop–Conconully gives 798 − 224 + 239 = $813 million, up $15 million.

(b) Adding Mazama–Twisp (223) closes the cycle Mazama → Winthrop → Twisp → Mazama, with tree roads Mazama–Winthrop (145) and Winthrop–Twisp (86). Removing Mazama–Winthrop gives 798 − 145 + 223 = $876 million, up $78 million.

Adding Twisp–Brewster (270) closes the cycle Twisp → Pateros → Brewster → Twisp, with tree roads Twisp–Pateros (261) and Pateros–Brewster (82). Removing Twisp–Pateros gives 798 − 261 + 270 = $807 million, up $9 million.

Removing the cheaper tree road instead raises the total more: 798 − 86 + 239 = 951, 798 − 86 + 223 = 935, and 798 − 82 + 270 = 986.

(c) No swap lowered the total. Each added road costs more than both tree roads on its cycle, so removing either one raises the cost. Removing the dearer of the two gives the smaller rise.

Task 4 covers all six swaps from Kruskal's tree: three unused roads, each with two tree roads on its cycle. None lowered the cost. Trees that differ from Kruskal's tree in two or more roads were not tried. A standard fact about spanning trees covers them as well [10]:

Swap test. If no single swap lowers the total weight of a spanning tree, that tree is a minimum spanning tree.

No swap lowers $798 million, so by the swap test no spanning tree of the town graph costs less. The county's cheapest plan is Kruskal's tree, at $798 million in 2014 dollars. As a cross-check, a computer added up all 24 spanning trees of this graph; $798 million is the lowest total, and only Kruskal's tree has it.

Kruskal's tree passes the swap test on every map, and step 1 is the reason. Each road the algorithm did not build was skipped, or never checked, at a moment when its two towns were already joined by built roads. Those built roads came earlier in the sorted list, so none of them costs more than the unused road, and they form the tree path between its two towns. Adding the unused road and removing one of them cannot lower the total. Kruskal proved that, when no two edges have the same weight, the tree his algorithm builds is the minimum spanning tree [8]. Lecture 10.3 explains why each choice Kruskal's algorithm makes is safe.

5. Prim's algorithm

A second method grows one group outward from a starting town. It is called Prim's algorithm, after Robert Prim, who published it in 1957; Vojtěch Jarník had described it in 1930 [9].

Prim's algorithm, for a connected graph with n vertices

  1. Pick any vertex to start. The group contains only that vertex.
  2. Look at every edge with one vertex inside the group and one outside. Build the cheapest of these edges, and put its outside vertex into the group.
  3. If the group contains all n vertices, stop. You have built n − 1 edges. Otherwise go back to step 2.

Prim's algorithm never makes a cycle, because each edge it builds brings in a vertex that had no built edges yet.

6. Running the algorithm again when a cost changes

FHWA states that real projects vary a lot around its typical cost [7], so a county reruns the algorithm whenever an estimate changes. The number in Task 6 is made up for the example.

Task 6 (about 3 minutes, paper)

Suppose a survey finds unstable slopes along the Twisp–Pateros route and the estimate rises from $261 million to $300 million (a made-up number). All other costs stay the same. Sort the roads again and run Kruskal's algorithm. Write the five roads built and the total cost.

Solution to Task 6

Twisp–Pateros moves to the end of the list. Rows 1 to 6 are unchanged: build Pateros–Brewster, Winthrop–Twisp and Mazama–Winthrop, skip Mazama–Twisp, build Winthrop–Conconully, skip Twisp–Conconully. Row 7 is now Twisp–Brewster (270). Twisp is in {M, W, T, C} and Brewster is in {P, B}, so it is built as the fifth road, and the algorithm stops.

Roads: Pateros–Brewster, Winthrop–Twisp, Mazama–Winthrop, Winthrop–Conconully, Twisp–Brewster. Total: 82 + 86 + 145 + 224 + 270 = $807 million. This is the tree from the Twisp–Brewster swap in Task 4. With the original estimate it cost $9 million more than Kruskal's tree; after the change it is the cheapest.
